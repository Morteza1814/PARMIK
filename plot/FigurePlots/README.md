# Paper figure reproduction

## Figure 3 — Recall versus minimum alignment size

Figure 3 in the PLOS ONE manuscript compares the recall of **PARMIK, BLAST, and Bowtie2** as the minimum accepted alignment length, **R**, increases. The queries are 150-bp sequences extracted from Wuhan-Hu-1 (`NC_045512`), searched against metagenomic reads from `SRR12432009`.

The experiment uses **K=11, PI=90%, and PARMIK M=4, IKT=all, with polishing enabled**. `IKT0` in the directory name means all k-mers are included.

- **Panel A:** recall for minimum alignment lengths from 11 to 150 bp.
- **Panel B:** a zoomed bar chart for `21 <= R < 35` (the script's upper slice boundary is exclusive).

The figure shows PARMIK's larger recall advantage at short alignment lengths and the convergence toward high recall at longer lengths. At R=21, the differences are approximately **21 percentage points versus BLAST** and **24 percentage points versus Bowtie2**.

[`recall_PARMIK_BLAST_fig3.py`](recall_PARMIK_BLAST_fig3.py)

The script generates **Figure 3** in the current manuscript. It accepts one positional argument: the directory containing the input count files.

### How the TP/FN files were generated

The workflow is:

```text
Tool alignment results + Smith–Waterman baseline
    -> PARMIK comparison mode (-a 4, -l <tool>)
    -> cmp_Baseline_<tool>.txt              detailed comparison report
    -> cmp_Baseline_<tool>_AlnSz_tp.txt     counts grouped by alignment length
    -> cmp_Baseline_<tool>_AlnSz_fn.txt     counts grouped by alignment length
    -> recall_PARMIK_BLAST_fig3.py
    -> Figure 3 PDF
```

The original comparison jobs are:

| Tool | Job that generated its comparison report and TP/FN files |
| --- | --- |
| PARMIK | [cmp_parmik_IKT0_K11_PI90_M4_T1_SC1_P_2484_1111_2444_2288_2848.slurm](../../experiments/parmik/IK_SSW_PF/SRR12432009/NC_045512/cmp_parmik_IKT0_K11_PI90_M4_T1_SC1_P_2484_1111_2444_2288_2848.slurm) |

| Bowtie2 | [cmp_bowtie_K11_PI90.slurm](../../experiments/parmik/IK_SSW_PF/SRR12432009/NC_045512/cmp_bowtie_K11_PI90.slurm) |

Each job uses `-a 4`, `-l parmik|blast|bowtie`, and `-d 90`. The `-b` argument supplies the tool alignment file, and `-z` supplies the baseline directory. For PARMIK specifically, `src/main.cc` replaces the supplied `-b` path with the experiment directory's `parmikAln.txt`. The PARMIK job still lists an older `CK_SSW_ID_PRCNTG/.../pmAln_*.txt` path; its run log confirms the replacement.

For each query, the comparator selects one alignment per database read, preferring greater alignment length and then fewer edits. Accepted tool alignments increment the tool TP histogram at the tool's alignment length. Baseline pairs missing from the accepted tool hits increment the tool FN histogram at the baseline alignment length. The files contain:

```text
AlnSz_tp.txt: length    baseline_TP_count    tool_TP_count
AlnSz_fn.txt: length    baseline_FN_count    tool_FN_count
```

The original implementation also counts accepted tool hits absent from the baseline as TP. Queries with no tool hits increment a query-level FN counter but skip the per-length FN histogram update. These details affect interpretation of the saved recall values.

All three detailed reports and all six histogram files are written into the **same Figure 3 data directory** listed above, including the BLAST and Bowtie2 comparisons. The `.out` files beside the `.slurm` scripts are execution logs; the comparison results live under `/p/lava/.../IKT0_K11_PI90_M4_T1_SC1_P_2484_1111_2444_2288_2848/`.

## Integrating existing minimap2 SAM output

The existing output found during inspection is:

```text
/p/lava/parmik/partialMatcherProject/tools/minimap2/SRR12432009/NC_045512/minimap2_parmik (1).sam
```

Only its header and five records were inspected; the comparison has not been run
on this file. It contains ordinary `M` CIGAR operations and `NM:i` edit counts.
The new [`Minimap2Reader.h`](../../src/Includes/Minimap2Reader.h) reads these as:

```text
alignment length = M + = + X + I + D       (exclude clipping)
substitutions    = NM - I - D
matches          = alignment length - substitutions - I - D
identity         = matches / alignment length
```

`NM` includes substitutions and inserted/deleted bases, as specified by the
[SAM optional-field specification](https://samtools.github.io/hts-specs/SAMtags.pdf).
This avoids counting indels twice or treating every `M` column as a match.
Explicit `=/X` CIGAR is also supported, with optional `NM` consistency checking.
Minimap2's output formats are described in its
[manual](https://lh3.github.io/minimap2/minimap2.html).

Use comparison mode `-a 4 -l minimap2 -b "/path/to/existing.sam"`, retaining the
other arguments from the existing baseline-comparison job. Set `-o` to a separate
writable output directory to keep the original experiment results intact.
This mode evaluates saved alignments; it does not invoke minimap2 or construct
new alignments. The input baseline directory remains the existing `-z` directory.
Like the other tools, reports are placed in the experiment subdirectory under
`-o`, with these additional histogram names:

```text
cmp_Baseline_minimap2_AlnSz_tp.txt
cmp_Baseline_minimap2_AlnSz_fn.txt
```

The comparator uses the same per-query/read selection (longest alignment, then
fewest edits) and TP/FN convention described above. All mapped primary, secondary,
and supplementary records are candidates; split records are not joined. Unmapped
records are ignored. Numeric query/read names or names ending in a dot followed
by a numeric ID must correspond to the original baseline IDs. SAM order does not
matter. PAF and spliced CIGAR operations are unsupported. Malformed input, missing
`NM` for `M` CIGAR, inconsistent edit counts, and alignments exceeding the existing
255-column `Alignment` representation produce an error instead of partial reports.
Errors now propagate to the command's exit status. [`src/Makefile`](../../src/Makefile)
tracks changes to the parser headers and `main.cc` when rebuilding.

`M` plus `NM` does not locate substitutions, so minimap2 uses numeric identity
for acceptance and does not report the exact-match-run diagnostic. That diagnostic
does not reject legacy tool hits either. Historical behavior, including omitted
per-length FN counts for queries with no tool hits and tool-only hits counted as
TP, is retained. These plotted values reproduce that convention rather than a
corrected exhaustive pair-recall metric; saved minimap2 output also limits which
hits can be evaluated.

The Figure 3 script automatically adds **MINIMAP2** in dark orange when both
minimap2 histograms are present alongside the six original histograms. With only
the original files it produces the original three-tool figure. Existing colors,
fonts, figure size, bar width, panel labels, and the `21 <= R < 35` zoom are retained.
The original cumulative recall calculation includes all supplied length bins,
while the displayed range is 11 through 150. TP/FN lengths must match within and
across tools; malformed or incomplete histogram pairs raise errors.

```bash
MPLBACKEND=Agg python3 plot/FigurePlots/recall_PARMIK_BLAST_fig3.py \
  /path/to/histograms --include-minimap2 --no-show \
  --output /path/to/new/Figure3_with_minimap2.pdf
```

`--include-minimap2` requires the additional pair instead of silently plotting
three tools. `--output` permits plotting from a read-only data directory. Without
`--output`, a four-tool run writes `PARMIKvsBLASTvsBOWTIEvsMINIMAP2_recall.pdf`
in the input directory; the three-tool default filename is unchanged.
